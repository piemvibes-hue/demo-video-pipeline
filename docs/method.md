# 方法论：一条能过评审的产品演示视频怎么做出来

这是把 6 版迭代 + 一次严苛独立评审踩过的坑全部沉淀下来的操作手册。按顺序做，别跳步。

---

## 0. 先定叙事：一案到底，不是功能巡礼

**反例（我们 v4 犯的错）**：12 个场景 = 12 个功能点轮流介绍，评委看完记住的是"功能很多"而不是"这东西怎么帮我"。

**正解**：找一条真实用户故事线，让每个功能在它该出现的位置自然出场。EmpathyDesk 的线：买家怒吼进线 → 它自动浮到队列最上 → AI 建议卡 → Agent 轨迹 → 合规护栏 → 买家被接住 → 插件外挂 → 看板闭环。10 场讲完一个案子。

写场景表时给每场一句话回答："评委在这一场应该记住什么？" 答不上来的场砍掉——砍掉的合并进主线一句话带过。

## 1. 录镜头：真机录屏，不是概念图

**铁律：赛题/评审要的是"实际使用时的演示"。** 全片镜头必须是真实产品的操作录屏，地址栏、流式生成、toast 都是系统真实表现。

- Playwright `recordVideo` 开在 **context** 上；每段一个 context，`ctx.close()` 才落盘 webm
- 每段之间 `sleep` 必须给足：SPA 渲染、动画、接口延迟——急点会录到半加载帧，后期没法救
- 录制前先 **dry-run 拿时间轴**：每个动作在素材第几秒发生，这是后面剪 `from`/`to` 的依据
- 出问题的功能**先修再录**：我们录 embed 插件时录到「等待宿主下发会话」卡死，结果是握手竞态 bug——视频倒逼修了一个真 bug
- 折叠卡片、异步面板这类组件**录前先点开**，别指望录制中操作员想起来

## 2. 剪场景素材：只留动作，裁掉死帧

`cut-merge.sh` 按区间拼素材。原则：

- **裁掉每段开头的登录/加载段**（一般 5-8 秒）——这是「画面滞后口播」最大的元凶
- 跨文件拼接一条完整动线（预警→拦截→回访→闭环三段合成一条 42s 素材）
- 播放速率 1.1–1.5x 微调对齐配音时长；>1.6x 鼠标会抽风，慎用

## 3. 配音稿：口语化 + 一种语气走全程

- `constants.ts` 的 `VO` 表是**唯一文本源**——字幕、场景时长、徽标时机全从它派生
- 写成说的样子：「V I P」「A I」「九成一点三」——TTS 照字面念
- **emo 全片统一**（我们选「路演讲解者：自信清晰、专业有说服力、节奏明快」）。逐场景换「紧迫/温暖/激昂」会让配音像几个人拼的，评审直接点名过
- 长稿不超时：中文朗读约 4–5 字/秒，一场别超 ~80 字/18s

## 4. 词级对齐：whisper + difflib 软对齐

`sync-timing.py` 做的事：

1. Whisper 对每段配音给**词级**时间戳
2. `difflib.SequenceMatcher` 把识别文本软对齐回配音稿——TTS 会把「95%」念成「百分之九十五」、漏字多字常见，直接字符串匹配必死
3. 词时间均摊到期望的每个字符，产出 `timing.ts`
4. 场景时长 = 配音时长 + 0.5s 交叉淡化，回写 `SCENES`

**不要去对 TTS 的输出做手工逐字切分**——识别反推永远比猜准。

## 5. 场景合成（Remotion）

每个场景固定四件套：

```tsx
<SceneTransition>              // 首尾 15 帧交叉淡化
  <GradientBackground />        // 渐变底，dramatic=开场/收尾，calm=正片
  <Audio src={scene.mp3} />     // 配音
  <ClipStage from={N} />        // 录屏+浏览器壳；from 跳到动作点
  <BadgeRow>{said("短语") && <FeatureBadge/>}</BadgeRow>  // 念到才出现
  <SyncedCaption scene={name}/> // 句级字幕
</SceneTransition>
```

- **`from` 是从评审意见里长出来的**：画面滞后口播 2–3 秒会被认为「配音是后配的、录屏在凑」。把 from 挪到动作点上
- **徽标时机用 `said("短语")`**：念到那句话徽标才出现——注意力被牵着走，比时间戳硬编码好维护
- **字幕句级断句**：`SyncedCaption` 按 。！？；——断句，一次一行逐字高亮；整段糊屏评委跟不上
- 进度 1.5x 以内的微调用 `rate`，别靠改帧率

## 6. 收尾场：三数字 + 一句口号

- 三个能实测的数字（准确率/召回率/成本），不要形容词
- 开源底座/技术栈一句带过
- 品牌名 + slogan 收尾——评委最后记住的是你的作品名

## 坑位清单（全是真实踩过的）

| 坑 | 症状 | 解法 |
|---|---|---|
| 画面滞后口播 | 念到 X 画面还没切到 X | 录屏 `from` 跳到动作点；合并素材裁死帧 |
| 整段字幕糊屏 | 评委读不完 | 句级断句，一次一行 |
| 配音情绪分裂 | 像几个人拼的 | 全片一个 emo |
| 录到功能 bug | 素材废掉 | 先修再录——视频是 e2e 测试 |
| 卡片折叠没展开 | 关键组件没出镜 | 录制脚本里先 click 展开再截 |
| 拉伸变形 | UI 截图塞进 16:9 框被拉宽 | 读真实尺寸 contain-fit，别硬填比例 |
| 词索引当字索引用 | 徽标提前/不出现 | `mentionAt` 按字符偏移找起点，别用数组下标 |
| 静态元素被背景盖掉 | JSX 在 DOM 里、opacity 也是 1，但渲染图里就是不存在 | GradientBackground 是 position:absolute 的整屏 AbsoluteFill——CSS 层序里 positioned 元素永远画在 position:static 内容之上，跟 DOM 顺序无关。场景里的普通静态 div 必须带 transform（FadeSlide）或 position:relative 才能露脸；模板 `center` 已带 position:relative，自定义内容容器照抄这一条 |

## 时长建议

官方无硬性要求时：**2–3 分钟**。太短显得没演透，太长评委没耐心。我们的经验值：10 场 × 平均 15s ≈ 150s，落在下沿偏中——每条故事线都演透但不注水。
